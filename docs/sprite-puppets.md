# Sprite puppets

Open **More options → Sprite puppets** in Studio. **Face controls** can hold the head angle, either eyelid or the mouth independently while the other tracks keep playing. Use **Face close-up** to see the drawings. **Key at playhead** records just the controls you moved. **Follow timeline** releases those preview overrides. The timeline also supports editing individual joint and drawing keys.

**Save puppet file** writes the rig, artwork and clip to portable JSON. **Open puppet file** reopens it. **Export website** embeds the document and player in one offline HTML file.

**Four on the Porch** has 49 head and shirt views from profile to front. Three original drawings anchor the turn. The baker calculates one correspondence per pair, then samples the original paint for each of the 46 intermediate angles. Each eyelid and the smile-to-whistle mouth has 11 poses per angle. The far eye is hidden in profile. All performers share one 1920 × 2690 WebP atlas, about 19.7 MiB decoded. The whistle is a mouth pose without audio.

The head and facial artwork came from the original Adventures zombie toy reference. The ImageGen source sheets in `examples/characters/porch-zombie-art` provide a continuous waist-to-boot painting, a shoulder-to-fingertip painting, three shirt views and three counting-hand poses. A separate palm-facing drawing supplies the waving hand. The thumb points inward in the raised wave. Draw-order keys carry the entire far arm behind the waistband and trouser legs as it lowers. The far eye uses a separate, progressively occluded drawing during the turn. The baker samples overlapping pieces in each joint's coordinate system. Both thighs attach to the pelvis. Its rotation track counterbalances the chest while the supporting boot stays planted. The upper arms pivot inside the shoulder caps. Each sleeve follows its arm through weights painted across the shirt, with the collar and waist pinned. Editing a shoulder rotation key also changes the sleeve in playback and website exports. To reproduce the atlas and weights, run `python tools/bake-porch-face.py original.puppet.json output.puppet.json` with the original 16-cell document from Posecraft commit `35aac31`.

The runtime is exported from `posecraft/sprite-puppet`. Validate an imported document with `validateSpritePuppet`, call `compileSpritePuppet` once per bind pose, then use `sampleSpritePuppet` for joint centers, rotations and tile indices, or `drawSpritePuppet` for canvas playback. Parts are stored in parent-first order with rest centers in a common coordinate system. Each pivot is a signed distance along its local Y axis. The first matching base drawing variant wins. Each optional layer then samples its own drawing channel and the current view. Interpolated drawing channels round to the nearest registered cell. Existing step-keyed documents keep their original timing.

A part can bind its paint to child joints with a `skin`. Each drawing view stores joint pivots in tile pixels and a square grid of joint weights. A shoulder rotation changes the drawing about its registered socket. Players sharing an atlas reuse the resulting bitmaps. The cache holds up to 20 MiB of painted poses per atlas. The porch clip uses 279 distinct bent-shirt poses at 60 Hz, about 18.9 MiB in total across all eight performers.

Adventures' Porch binds this performance to assembled zombie decorations. Standard assemblies share a compiled rig and sampled poses and draw to one canvas per performer. Individually customized assemblies use separate painted layers. Both paths use the same drawing, joint and draw-order tracks. The performance document in `src/game/porch-zombie.puppet.json` is the same file that opens in Studio. To update the performance, replace that file with the reviewed Studio export and rebuild the game. The game's bind pose, placement and purchases remain in its own save.

For a hot-reloading seeded town, set `BENCH_ZOMBIES=8` and run `node --experimental-strip-types test/adventures-building-performance.mjs 960 --dev` in Posecraft. This starts Adventures Vite on port 5272 with an isolated local save.

Add `--navigation` to seed a second owned home and exercise touch swipes and three Star Map round trips. To measure the built game, use a width of 390, set `BENCH_HEADED=1` and omit `--dev`. The benchmark checks that the original artwork and animation clocks survive those trips, then drags a decoration for 14.5 seconds while all eight performers play.

On November 25, 2026, foreground Edge 158 on Windows with Intel Iris Xe graphics ran the production lot at 390 × 844 CSS pixels and DPR 2. With eight 14-piece performers and 36 loose decorations, the 14.5-second drag averaged 60.0 FPS and its slowest frame took 17.7 ms. Yard and home swipes averaged 59.6 and 59.3 FPS. Three Star Map returns averaged 56.5–58.2 FPS, with one 66.7 ms frame. Opening the compact editor produced a 100.1 ms frame. All eight performers continued during subsequent appearance edits and rotation. These measurements used an emulated touch viewport on a desktop GPU.
