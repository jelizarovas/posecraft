# Additive motion layers

`motionLayers` adds movement to an authored pose before contact constraints are solved. Studio → Scene → Motion & website edits the actor, joint, channel, source, amplitude, frequency, phase and seed. Sine/noise sources use time; a numeric scene variable can control their strength over an increasing range. The data API can restrict any layer to selected clips.

An `input` source requires exactly one numeric scene `variable` or pack `input`, and an increasing `range`. Actor inputs are sampled from the current actor frame and can be driven by an independent actor behavior graph. Its decisions and bounded rates continue during scene activities, so a timed head glance can finish while a typing action and hand inputs keep running. Preview suspension and scene ownership of the action clip remain intact. It maps the lower endpoint to negative amplitude, the midpoint to zero, and the upper endpoint to positive amplitude, clamping values outside the range. A held value stays still as scene time advances. Frequency, phase and seed remain required saved fields but do not affect input. Bend outputs remain clamped to 0–1; use two oppositely authored bend layers when both deformation directions are needed. Input remains additive to the current action, including its displayed morph contour during interruptions. Existing clip filters can exclude action poses such as throwing or resting.

For example, `{id:'hand-x', actor:'character', joint:'hand', channel:'x', type:'input', amplitude:18, variable:'keyX', range:[-1,1], frequency:1, phase:0, seed:0, clips:['typing']}` adds −18 to +18 scene units. The host supplies bounded values with `player.setVariable('keyX', value)`; scene data contains no DOM or keyboard dependencies. Studio creates a neutral `motionInput` variable if the scene has no numeric variables when Input is selected. Actor inputs appear as `input:attention` (for example) in the same Studio source menu. Selecting one clears the scene-variable source. Save/reopen and compiled exports retain the binding. Package consumers opt in with the tree-shakable `applyMotionLayers` export from `@posecraft/runtime/features`, passed as `motionLayerSolver`. Independent actor graphs use the named `ActorBehaviorRuntime` export as `actorBehaviorFactory`.

Declare `motion-layers`. A scene supports up to 64 layers. Frequency is 0.05–12 Hz; amplitude is 0–30 scene units/degrees, or 0–1 for bend. Noise interpolates seeded samples smoothly. Time sampling is deterministic and poses remain within rig constraints. Studio pose previews and physical/recovering actors bypass these additions. Paused/reduced-motion scenes remain still; an explicit seek can inspect a requested sample.

Gym now uses a small torso breathing layer and fatigue-dependent effort noise. Existing asymmetric rep timing, rest/recovery, constrained grips, connected skin and corrective deformation remain in the shared rig/action data. These small layers do not replace anatomy or create a general muscle simulation. Edit mesh corrective shapes in the Surface tools and contacts in Contacts & grips.

The lightweight compiler selects the motion-layer provider when used. `test/motion-layers.test.js` verifies repeatability, clamping and preview exclusion. The real Gym export browser check verifies full/lightweight pose agreement with no Planck dependency.

`opacity` is also an additive channel, with amplitude and final output clamped to 0–1. It works on ordinary or spatial joints. An unset layer baseline is zero. The day/night sky uses an input layer to fade existing artwork without replacing its action clip.
